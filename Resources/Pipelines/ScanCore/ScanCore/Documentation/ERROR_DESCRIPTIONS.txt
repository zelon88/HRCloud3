APPLICATION INFORMATION ...
This application is designed to scan files & folders for viruses.

FILE INFORMATION ...
v2.0.0.
This plain text file describes every numbered error that ScanCore can raise, & every warning that it can write.

ADDITIONAL INFORMATION ...
An error carries a number, & the number never changes. A number that is retired is not used again.
A warning carries no number. It says that something happened & stops nothing.
To find an error, search this file for its number, written as it is printed, such as ScanCore-610.
To find a warning, search this file for the words of it that do not change.
Documentation/ABOUT_REPORTS.txt says how an entry is written to the report & how it is printed.

HARDWARE REQUIREMENTS ...
This application requires at least a Raspberry Pi Model B+ or greater.
This application will run on just about any x86 or x64 computer.

DEPENDENCY REQUIREMENTS ...
This application requires PHP 8.0 or later, run from a command line on Linux or Windows.
The zlib extension reads compressed container members & png chunks, which are reported as incomplete without it.
An update uses Git, or downloads each file with PHP, or with cURL where PHP may not open a URL. None of them is needed to scan.
The posix extension hands new files to the owner of the installation when ScanCore is run as root.

--How To Read An Entry--

ERROR MESSAGE
  The error as it is written to the report. A part in angle brackets is filled in when the error is raised.

FILE
  The file that raises it.

FATAL
  YES where ScanCore stops & exits 1. NO where it carries on.
  An error that is not fatal is often followed by one that is, which is named in the description.

LOGGED
  YES where the error is written to the report. NO where it is raised before the report can be used,
  & is printed on the console alone.

ERROR DESCRIPTION
  What happened, why, & what to do about it.

Errors 1 to 99 stop ScanCore. Errors from 100 up say what went wrong in one part of it.

  100    Arguments.                      500    Definitions & classifiers.         800    The configuration backup.
  300    The path to scan.               600    Reading a file.                    900    The report & the update guard.
  400    Definition updates.             700    Application updates.

ERROR MESSAGE
  ERROR!!! ScanCore-1, Cannot verify the ScanCore installation!  <reason>

FILE
  /ScanCore.php

FATAL
  YES

LOGGED
  NO

ERROR DESCRIPTION
  ScanCore checks where it is running before it does anything else, & one of four things was wrong.

    ScanCore only runs from a command line interpreter
        It was reached through a web server or another interface. Run it with the php command.
    ScanCore requires PHP 8.0 or later, found <version>
        Run it with a newer interpreter.
    A required PHP function is unavailable:  <function>
        The function is switched off in php.ini, under disable_functions, or its extension is not loaded.
    Cannot resolve the ScanCore installation directory
        The folder that holds ScanCore.php could not be resolved to a real path.

WARNINGS ABOUT THE CONFIGURATION

    WARNING!!! ScanCore on <time>, Configuration entry $<name> is missing or invalid, using the built in default instead.
        An entry of ScanCore_Config.php is absent, or is not of the kind that it should be.
        The default that is built into the core was used for this run. Correct the entry, or restore it from the release.

    WARNING!!! ScanCore on <time>, Configuration entry $InstallDir does not contain <core>, using <folder> instead.
        The configuration file was loaded from another folder & names a folder that does not hold the core.
        The folder that does hold it was used. Set $InstallDir in that file to the folder that holds ScanCore.php.

    WARNING!!! ScanCore on <time>, Configuration entry $UpdateMethod is not git or raw, using git instead.
        Set --Update Method-- to 'git' or to 'raw'.

    WARNING!!! ScanCore on <time>, Configuration entry $DefsFile does not exist, using the file beside the core instead.
        The definitions file that the configuration names is not there, & one with the configured name sits beside the core.

    WARNING!!! ScanCore on <time>, The -configfile argument was supplied without a path, using the default instead.
        -configfile was the last argument. ScanCore_Config.php was loaded.

    WARNING!!! ScanCore on <time>, The -defsfile argument was supplied without a path, using the configured file instead.
        -defsfile was the last argument. The configured definitions file was used.
----------------------------------------------------------------------------------------------------------------------------------------------------------------

----------------------------------------------------------------------------------------------------------------------------------------------------------------
WARNINGS ABOUT ARGUMENTS

    WARNING!!! ScanCore on <time>, The <switch> argument was supplied without a value, using the configured value instead.
        A switch that takes a value was the last argument.

    WARNING!!! ScanCore on <time>, The <setting> value is missing or below the minimum of <n>, using <n> instead.
        A number was not a number, or was too small to work with. A number is written in digits & carries no suffix.

    WARNING!!! ScanCore on <time>, The <budget> of <n> does not fit the MemoryLimit, using <n> instead.
        ChunkSize, MaxArchiveEntrySize or MaxImageChunkSize was lowered for this run so that the scan fits its memory limit.
        A file that is larger than the lowered budget is inspected in part & is reported as incomplete.
        Raise -memorylimit, or lower the budget, to stop the warning.

    WARNING!!! ScanCore on <time>, The UpdateMethod override is not git or raw, using git instead.
        -updatemethod takes git or raw.

    WARNING!!! ScanCore on <time>, No scan path was supplied, falling back to the configured ScanLoc.
        ScanCore was run with no arguments, & scanned --Scan Location--.

    WARNING!!! ScanCore on <time>, Cannot build version information!
        The answer to -version or -help could not be put together. This is not expected to happen.

    WARNING!!! ScanCore on <time>, Cannot apply the configured MemoryLimit to the interpreter.
        PHP refused the memory limit, & kept the one that php.ini gives it.

    WARNING!!! ScanCore on <time>, Ignored <n> malformed classifier records.

WARNINGS ABOUT A SCAN

    WARNING!!! ScanCore on <time>, Cannot read the contents of a folder, it was skipped:  <path>
        The account that runs ScanCore may not list the folder. Nothing in it was scanned. This is printed as well.

    WARNING!!! ScanCore on <time>, Reached the maximum scan depth, this folder was not opened:  <path>

WARNINGS ABOUT UPDATES

    WARNING!!! ScanCore on <time>, Definition updates are disabled in the configuration file.
        --Allow Definition Updates-- is FALSE. ScanCore-7 follows.

    WARNING!!! ScanCore on <time>, Application updates are disabled in the configuration file.
        --Allow Application Updates-- is FALSE. ScanCore-8 follows.

    WARNING!!! ScanCore on <time>, Cannot reach the configured update host:  <host>
        The host did not accept a connection. ScanCore-400 or ScanCore-700 follows.

    WARNING!!! ScanCore on <time>, Cannot find a usable git binary.
        The git method was asked for & git could not be run. The raw method is tried next.
        Install git, or set --Update Method-- to 'raw', to stop this warning.

    WARNING!!! ScanCore on <time>, The git clone operation did not produce a directory:  <what git printed>
        git ran & downloaded nothing. What it printed says why. The raw method is tried next.
